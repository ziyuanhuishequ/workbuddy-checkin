# WorkBuddy 自动签到

服务端常驻的网页控制台：**一条链接发给所有人，各人自己把账号交进来**，服务器每天定时自动签到。
不用开电脑、不用装客户端、不用守着点。

```
对方打开 /join → 电脑端登录 或 上传令牌文件 → 服务器拿到登录态 → 每天 09:00 自动签到 → 结果留档 + 可选推送到群
```

---

## 功能

| | |
|---|---|
| 🖥 **电脑端登录** | 页面上一个按钮，点了就在新标签页打开官方登录页（自己带二维码），用手机微信扫**电脑屏幕**即可，**不需要在服务器上装浏览器**（纯 HTTP 协议实现） |
| 📄 **上传令牌文件** | 不想碰电脑命令行的人走这条：把 `credentials.json` 整份**拖进去**就行，服务器自己认字段、自己解析，不用挑哪个是 accessToken |
| 👥 **多账号** | 账号数量不限，逐个添加即加即用；每个账号独立会话，互不干扰 |
| 🔗 **一条链接给所有人** | `/join?t=…` 是一条**公共自助链接**，发给谁都能用：对方在上面自己加自己的账号、当场拿到查看凭据，**完全不需要你的控制台密码，也看不到任何别人的数据**。原链接可一键作废重发 |
| 👤 **用户自助页** | 每个账号自动配一套**独立的前端账号密码**。对方打开 `/me` 登录后，只能看到**自己那一个账号**的积分余额、今日签到状态、今日获得积分和签到记录，还能自己暂停签到、改密码，或退出登录删除凭据 |
| 🔐 **隐私友好** | 登录页和自助页都明确写明**不收集、不上传任何信息**，仅作小范围签到使用；凭据只留在你自己的服务器上，用户随时能自助删除 |
| ⏰ **每日自动签到** | 每天到点自动批量签到，时间可改；**服务重启 / 服务器宕机后会补签**当天没签的账号 |
| 🔁 **失败重试** | 签到失败按间隔自动重试，可配置每天最多重试几次 |
| ♻️ **令牌自动续期** | 快过期提前续、接口回 401 也会先自动续期再重试签到；后台每 2 小时保活一次，**加一次就长期不用管** |
| 🩺 **失效自愈** | 账号被标「需重新登录」时点一下「自动修复」：自动续期 + 补签，续不上才需要重新加一次 |
| 🌐 **域名容灾** | 上游主站 `www.workbuddy.cn` 不通时自动切换备用域名，登录链接与接口域名自动对齐 |
| 🧾 **宽容解析** | 对方粘过来的东西是什么形状都行：整份 `credentials.json`、从里面只抄两行、外面还带着一堆说明文字、甚至 CSV —— 都能认出来（详见 [用户教程-上传令牌.md](docs/用户教程-上传令牌.md)） |
| 📊 **控制台** | 账号列表（昵称 / 积分 / 今日状态 / 令牌到期）、一键全部签到、全部自检、签到日志 |
| 🔔 **结果通知** | **两套**：管理员在「设置」里配一个群 webhook（企业微信 / 钉钉 / 飞书 / Server 酱 / 自定义）；**每个用户还能在自助页配自己的 Server 酱**（个人微信） |
| ✅ **登录完成通知** | 每次登录成功（电脑端登录 / 上传令牌 / 失效后自动续期救回）都推一条个人微信：**今日积分是多少、本次签到拿到多少、明天预计多少** |
| 🆘 **失效引导** | 账号失效的通知里直接写清**去哪儿重新登录**（签到面板 + 自助页），以及**联系站点管理员**的入口（可用 `WB_SITE_OWNER` 换成你自己的地址） |
| 🔒 **安全** | 控制台密码 + 签名会话、登录限流、凭据加密落库、写操作拒绝跨站来源、管理员与用户令牌严格隔离 |

前端是单文件、零外部依赖（不加载任何 CDN），断网内网也能正常打开。

## 快速开始

### 服务器部署（宝塔面板）

```bash
# 把项目上传到服务器后，在项目根目录执行
bash deploy/install-bt.sh
```

脚本会自动装依赖、生成密码、注册 systemd 服务并做一次接口自检，最后把访问地址和密码打给你。

详细步骤（含图形化操作、Nginx 反代、HTTPS、备份升级）见 **[部署文档.md](docs/部署文档.md)**。

### 本机试跑

```bash
pip install -r requirements.txt
python run.py
```

打开 <http://127.0.0.1:8848>。首次启动会把自动生成的控制台密码打印在终端，同时存到 `data/password.txt`。

### Docker

```bash
echo "WB_PASSWORD=你的强密码" > .env
docker compose up -d --build
```

### 把一条链接发给所有人（不用给他控制台密码）

控制台「设置」页 →「**分享给他人自助添加**」→ 复制那条带令牌的链接：

```
https://你的域名/join?t=xxxxxxxx
```

**这一条链接可以发给所有人**，不用一人一条。对方打开后页面上有两个卡片：

- **方式一 · 电脑端登录** —— 点「🖥 打开电脑端登录页」，新标签页里是官方登录页，手机微信扫**电脑屏幕**上那个二维码即可
- **方式二 · 上传令牌文件** —— 把 `credentials.json` 整份拖进去。**只有装过命令行版的人才有这个文件**，
  桌面版 App 用户电脑里根本没有 → 所以卡片顶部已经用黄框标注「大概率你没有」，并给了「好，我用方式一」的回退按钮

两种都是他给自己加账号，**全程碰不到你的控制台，也看不到任何别人的账号**。加完当场显示属于他自己的查看账号密码。
链接可随时「换一个新链接」作废旧的。

> ⚠️ 如果对方是在**微信里**点开这条链接，页面会识别出来，只显示一个「复制本页链接，发到电脑打开」的提示 ——
> 微信内置浏览器打不开官方登录页（原因见 [常见问题](#常见问题)），也读不到本地文件，这是刻意设计的，避免他白折腾。

## 怎么用

### 管理员

1. 打开控制台，输入管理员密码登录。
2. 点右上角 **「+ 添加账号」**，里面有两个标签页，任选一个：

   **🖥 电脑端登录**
   - 点「**打开电脑端登录页**」→ 新标签页跳到官方登录页
   - **手机微信扫电脑屏幕上那个二维码** → 手机上点「确认登录」
   - 弹窗自动变成 ✅，并**立刻为这个账号补签当天的一次**

   **📄 上传令牌文件**
   - 把 `%USERPROFILE%\.codebuddy\instances\credentials*.json` 整份拖进虚线框（或点选文件）
   - 服务器自己解析令牌 / uid / 域名，直接入库

3. 添加成功后会直接弹出一张凭据卡片：**前端账号（如 `wb001`）+ 前端密码 + 登录地址 `/me`**，
   点「复制账号密码和地址」转交给这个账号的主人。

   > 没看到也没关系 —— 事后在账号列表点该账号的「前端」按钮，随时能重新查看和复制。
4. 重复第 2 步，把所有账号都加进来。

> 想立刻全部签一遍，点「一键全部签到」；想确认凭据是否还有效，点「全部自检」。

### 用户（拿到 `wb001` 那套凭据的人）

1. 打开 `https://你的域名/me`，用管理员给他的账号密码登录。2. 页面上能直接看到：
   - **可用积分余额**
   - **今日是否已签到**、**今日获得多少积分**
   - **累计签到成功次数**和**最近 30 天签到记录**
   - 每天几点自动签到、下次签到还有多久、凭据是否自动续期
3. 他还可以自己：
   - **暂停 / 恢复**自动签到
   - **修改自己的密码**（建议首次登录就改掉）
   - **退出登录并删除凭据** —— 一键把自己从这台服务器上完全移除

页面上明确写着：本站不收集任何信息，仅用于小范围 WorkBuddy 自动签到，凭据只保存在服务器本地、随时可自助删除。

> **密码怎么保管**：前端密码存两份 —— `pbkdf2` 哈希用于登录校验，Fernet 加密的明文供管理员查看和转交。
> 所以它**不是一次性的**：任何时候在账号列表点「前端」，账号、密码、登录地址都会显示出来，可以一键复制。
> 用户自己改过密码后，管理端看到的也会同步更新。
>
> 早期版本只存哈希、密码显示一次就找不回来了 —— 实战证明这行不通（对方光顾着看手机就错过了），已改为可查。

### 让对方自己动手（把教程直接转给他）

不想一个个帮忙加？把这两样发给他就行：

- 自助链接：`https://你的域名/join?t=xxxxxxxx`
- 图文教程：**[用户教程-上传令牌.md](docs/用户教程-上传令牌.md)** —— 按「小白」写的，每一步都写清点哪里、粘贴什么、看到什么算成功

## 微信通知会收到什么

用户在自助页 `/me` →「微信提醒」里填自己的 Server 酱 SendKey 之后，会收到三类消息。

**① 登录完成（每次登录都会发）** —— 电脑端登录、上传令牌、以及失效后自动续期恢复，都算一次登录：

```
✅ 登录已完成，签到服务已经自动接管，你不用再做任何操作。

账号：小明
方式：电脑端登录 / 上传令牌文件
时间：2026-10-27 14:20

📊 积分情况
· 今日积分：1,234
· 今日签到：+100 积分（本次已到账）
· 明日预计：1,334（其中明日签到约 +100）

🔗 查看明细：https://你的域名/me

────────────
❗账号哪天失效了，在哪儿重新登录？
1. 打开签到面板：https://你的域名
   用自己的管理员密码登录 → 点右上角「添加账号」重新登一次
2. 查看自己的积分：https://你的域名/me
3. 不会操作 / 需要帮处理：联系站点管理员
```

**② 每天签到结果**：同样的「今日积分 / 今日签到 / 明日预计」三行，加上签到结论。
**③ 凭据失效**：说明签到已暂停 + 上面那套「去哪儿重新登录 + 联系站长」的步骤。

口径说明（避免误解）：

| 项目 | 含义 |
|---|---|
| 今日积分 | 推送那一刻上游返回的**实时可用积分余额** |
| 今日签到 | 本次签到**实际到账**的积分；当天已签过则显示今日累计所得，并标注「本次未新增」 |
| 明日预计 | `今日积分 + 每日签到额度` 的**估算值**，额度取上游返回的 `daily_credit`（拿不到就用今日所得），实际以官方为准 |

> 想加「联系站长」的入口？设置环境变量 `WB_SITE_OWNER=你的站点或联系方式`，
> 所有通知和失效提示会一起带上它；不设置就只说「联系站点管理员」，不出现任何外部地址。

## 配置项

网页「设置」页可以直接改，保存即生效，不用重启服务：

| 设置 | 默认 | 说明 |
|---|---|---|
| 每日签到时间 | `09:00` | 服务器时区（默认东八区 UTC+8） |
| 启动时补签 | 开 | 服务重启后，补签当天还没签的账号 |
| 自动续期令牌 | 开 | 强烈建议保持开启 |
| 令牌保活间隔 | 2 小时 | 后台提前续期 + 自动复活失效账号，0 = 关闭 |
| 提前续期时间 | 30 分钟 | 距过期不足这个时间就续期（到期时间未知时也会续） |
| 上游接口域名 | `https://www.workbuddy.cn` | 主站不通时可换成备用域名，保存即生效 |
| 失败重试间隔 | 30 分钟 | 当天签到失败后多久重试一次 |
| 每天最多重试 | 3 次 | 单账号上限 |
| 上游代理 | 空 | 如 `http://127.0.0.1:7890` |
| 通知方式 / 时机 / 地址 | 不通知 | 支持企业微信、钉钉、飞书、Server 酱、自定义 |

> 通知怎么配？每种方式的入口都不一样，钉钉还有个「关键词」的坑 —— 见 **[通知配置教程.md](docs/通知配置教程.md)**（有一步步的图文说明）。

环境变量（`.env`）用于部署层面的配置，见 [.env.example](.env.example)。其中 **`WB_PASSWORD`** 和 **`WB_SECRET_KEY`** 是敏感项：

- `WB_SECRET_KEY` 变了，**已保存账号的令牌会解不开**，需要重新添加一次。
- `WB_PASSWORD` 留空会自动生成到 `data/password.txt`。
- `WB_ALLOW_MANUAL_IMPORT`（默认开）关掉后，自助页的「上传令牌文件」会被拒绝，只留电脑端登录。
- `WB_SITE_OWNER`（默认空）填了之后，账号失效/签到失败的通知里会引导用户去这里找站长。

## 工作原理

纯 HTTP 协议实现，不模拟点击、不开浏览器。上游主站是 **`www.workbuddy.cn`**（官方 CLI 2.177.x 的主域名），
`copilot.tencent.com` 与 `wb.tencentbuddy.com` 作备用，失败自动切换。

**登录**（插件通道 `/v2/plugin/auth/*`，需伪装成官方 CLI）：

1. `POST /v2/plugin/auth/state?platform=CLI` → 返回 `state` 和 `authUrl`
2. `authUrl` 形如 `https://copilot.tencent.com/login?platform=CLI&state=…`，**这条就是交给用户在电脑浏览器里打开的东西**
3. **域名对齐**：链接里的域名必须和轮询域名一致，否则上游把登录态绑在另一个域上，轮询永远停在「等待登录」
   （对应官方 CLI 的 `alignAuthUrlToApiOrigin`）
4. `GET /v2/plugin/auth/token?state=…` → 轮询，未完成时业务码 `11217`，登录确认后返回 `accessToken` / `refreshToken` / `domain`
5. `GET /v2/plugin/login/account?state=…` → 取昵称、uid（未就绪时业务码 `12151`，等一会儿再取）
6. 续期：`POST /v2/plugin/auth/token/refresh`，带 `X-Refresh-Token` + `X-Auth-Refresh-Source: plugin` + `X-Domain` + `X-Enterprise-Id`

> **`state` 是一次性的**：同一条登录链接点第二次必然失败，所以控制台和自助页每次点击都会**重新申请一条**，
> 并且同时轮询所有还活着的会话，谁先回来算谁的。

> **为什么不把 `authUrl` 渲染成二维码丢给手机扫**（v1.4.0 起已彻底删除）：
> 官方登录页 `www.codebuddy.cn/login/` 里有一段内联脚本，注释写着「微信内网员工探测（新版·前置）」「已全量放开，所有环境生效」，
> 判断 `ua.indexOf('micromessenger') !== -1 && ua.indexOf('wxwork') === -1` 就强制 302 到
> `open.weixin.qq.com/connect/oauth2/authorize?...scope=snsapi_base`，普通用户过不去，最后一屏就是「登录失败 / 请返回客户端点击重新发起登录」。
> 实测同一条 URL 用 PC UA 和微信 UA 抓下来都是同样的 23118 字节 —— 服务端没有按 UA 分支，纯粹是客户端脚本行为，改协议改不动。
> 结论：**只有「电脑浏览器打开 + 手机扫电脑屏幕」这一条路**，二维码图片反而是误导，所以删掉。

**上传令牌**（保底路径，不依赖上游任何登录接口）：

- 前端把整份文件内容 POST 给 `/api/join/import`（上限 256 KB）
- `service.parse_credentials_text()` 宽容解析：剥掉前后说明文字、按 `{` / `[` 重新切 JSON、
  大小写和下划线都不敏感地认 `accessToken` / `refresh_token` / `uid` / `domain` / `nickname`，
  还会往下一层找（官方就是这么放的：令牌在根上，`uid` 藏在 `credential.user.uid` 里）
- 纯文本也认：`accessToken=xxx`、`refreshToken: xxx`、`xxx,yyy,域名,昵称` 之类的 CSV 行
- 按 `(accessToken, refreshToken, uid)` 去重，同一个账号重复导入只会更新，不会变出两个

**自动续期（长期免维护的关键）**：

- 到期时间未知（`expires_at = 0`）也视为「需要续期」，不会像老版本那样一辈子不续
- 签到/自检一旦遇到 401/403，先强制续期再重试一次，只有续期也失败才标「需重新登录」
- 后台每 2 小时跑一次保活：提前 6 小时续期 + 把已失效但 refreshToken 尚存的账号自动复活
- 续期响应保持 refreshToken 滚动更新，字段名兼容 `accessToken` / `access_token`

**签到**（计费通道 `/v2/billing/meter/*`，网关会拦 python-requests 的默认 UA，必须带官方 UA）：

1. `POST /v2/billing/meter/checkin-activity-status` → 查今天签没签、活动是否开放
2. 没签才 `POST /v2/billing/meter/daily-checkin` → 领积分（业务码 `10001` 表示今天已签过，算正常）
3. 顺手尽力领 `claim-gift`（今日礼包，上游已下线时返回 404，静默跳过）
4. 积分余额：`POST /billing/meter/get-user-resource-summary`（注意这个路径**不带 `/v2`**）

接口是**幂等**的，同一天重复调用安全，所以重试和兜底都不会签坏。

**自检接口**：`GET /api/diagnose` 会依次打三个上游域名，告诉你哪个能通、登录链接能不能申请到。

## 目录结构

```
workbuddy-checkin/
├── app/
│   ├── config.py        # 环境变量与默认配置
│   ├── crypto.py        # 凭据 Fernet 加密
│   ├── db.py            # SQLite 持久化（账号 / 日志 / 设置）+ 老库自动迁移
│   ├── wb.py            # WorkBuddy 接口客户端（登录 / 续期 / 签到）
│   ├── qrlogin.py       # 登录会话管理（申请链接 / 轮询 / 取账号）
│   ├── portal.py        # 用户自助页凭据（生成 / pbkdf2 校验 / 改密）
```

## 常见问题

**点了「打开电脑端登录页」没反应？**
说明浏览器拦了新标签页。控制台和 `/join` 页上都有「复制链接」按钮，复制后手动粘到电脑浏览器地址栏也一样。
注意链接**只能用一次**，失败就再点一次按钮（每次点都会重新申请）。

**官方登录页显示「登录失败 / 请返回客户端点击重试」？**
说明这条链接是在**微信内置浏览器**里打开的。官方登录页有一段内联脚本专门探测微信环境，
识别到就把人踢去 `open.weixin.qq.com/connect/oauth2/authorize?appid=wxf3055eea2dff6d9c...`（内网员工探测），
普通用户过不去，于是显示「登录失败」。
解决办法：**把链接发到电脑浏览器打开**，再用手机微信扫电脑页面上那个二维码 —— 这条路径实测可用。

**一直提示「等待登录」？**
手机确认后需要几秒才会同步过来。若超过 1 分钟仍无反应，回到添加账号的窗口点一次「打开电脑端登录页」重新申请。

**「申请登录链接失败」？**
服务器访问不了 `https://www.workbuddy.cn`。检查 DNS、出网策略，或在设置里配代理。

**上传令牌后提示「认不出里面的令牌」？**
多半是粘的内容不对（比如把整个文件夹的地址粘进来了，或者只粘了文件名）。
让对方按 [用户教程-上传令牌.md](docs/用户教程-上传令牌.md) 重新找到文件，把**文件内容**整段拖进去。

**用户说「找不到 `credentials.json`」？**
这个文件是**命令行版**（`@tencent-ai/codebuddy-code`）登录后才生成的，**桌面版图形客户端根本不产出它** ——
所以桌面版用户找不到是正常的，不是他操作错了，任何工具也变不出来。
常见两种失手：① 路径里的**反斜杠 `\`** 被复制丢了（`%USERPROFILE%.codebuddyinstances` 必然找不到）；
② 位置不在默认目录（用「此电脑 → 搜索 `credentials.json`」）。
`tools/find-credentials.bat` 可直接发给对方双击：先查常见位置，没找到再按提示全盘搜一次，找到后还能一键复制内容到剪贴板。
确实没有时的三条出路：① 走「电脑端登录」（0 安装，永远有效）；② **对方公司/家里另一台电脑装过命令行版**——在
那台上把文件内容复制到微信「文件传输助手」，再粘进 `/join` 的「📋 直接粘贴文件内容」；③ 自己装 CLI 生成一个。
⚠️ 只能用**本人账号**的文件，拿别人的导进来签的是别人的号。
**实在搞不定就让对方走「电脑端登录」**，别在这条路上耗时间。

**用户说「我只有手机，没有电脑」？**
没办法绕：官方登录页必须在电脑上打开、拿手机扫电脑屏幕。手机浏览器里扫自己屏幕上的二维码不成立，
微信内置浏览器更是会被官方页面直接拦掉。让对方借一台电脑（网吧、公司、同事的都行），
或者在**装了 CLI 的那台电脑**上导出内容发到手机，再用手机浏览器打开 `/join` 走「直接粘贴文件内容」。

**上传令牌提示「内容太大了」？**
只该传 `credentials*.json` 本身，别把整个目录打包上传。上限 256 KB。

**失效账号越堆越多？**
账号页点「**🧹 清理失效账号**」（可选只清失效超 7 / 30 天的）；想让它自己清就在
「设置 → 签到 → 自动清理失效账号」里填 N（失效满 N 天自动删，`0` = 关闭）。
只删本服务器上的凭据，WorkBuddy 账号本身不受影响。

**账号显示「需重新登录」？**
先点这个账号上的 **「自动修复」**：服务器会用 refreshToken 自动续期并补签，多数情况直接恢复。
只有提示「续期被拒绝」才说明 refreshToken 本身也过期了，这时重新加一次即可，
不需要删除旧账号——按 uid 会自动覆盖更新。

**积分/昵称不显示？**
说明计费接口返回异常。点该账号的「自检」，会显示上游原始错误信息。

**改了设置不生效？**
网页保存是立即生效的。只有改 `.env` 才需要 `systemctl restart workbuddy-checkin`。

**会不会一天签两次？**
接口幂等，第二次只会返回「今日已签到」，不会重复发积分。

## 安全说明

- 凭据（accessToken / refreshToken）**只存在你自己的服务器上**，用 Fernet 加密后落库；密钥由 `data/secret.key` 派生。不会上传到任何第三方。
- 控制台**强制要求密码**，密码不会以空值启动。会话 Cookie 是 HttpOnly + SameSite=Lax 的签名令牌；登录失败会限流。
- **默认只监听 `127.0.0.1`**。请通过宝塔的 Nginx 反向代理 + HTTPS 对外提供访问，不要直接把端口暴露到公网。
- `/join` 链接等同于「允许对方往你这台机器加一个自己的账号」。**别公开贴到公网**，只发给信任的人；发现外泄就点「换一个新链接」作废旧链接。
- `data/` 目录含全部账号凭据，**备份时注意保管，不要提交到 Git**（`.gitignore` 已排除）。
- 建议只签你自己的账号。
