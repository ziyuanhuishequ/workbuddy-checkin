# v1.2.0 更新说明：登录完成通知 + 失效引导

> 一句话：**每次登录成功都会给你发一条微信，写清「今日积分 / 本次签到所得 / 明日预计」；
> 账号哪天失效了，消息里直接告诉你到哪儿重新登录、找谁帮忙。**

---

## 一、这次新增了什么

### 1. 登录完成通知（每次登录都发）

触发时机（三种都算一次登录）：

| 场景 | 说明 |
|---|---|
| 扫码登录成功 | 控制台或 `/join` 扫码添加/重新扫码 |
| 手动导入成功 | 单个导入、批量导入（`rt:` 形式也算） |
| 失效后自动救回 | 凭据被判失效 → 用 refreshToken 自动续期成功，**不需要你重扫的那种** |

消息里固定包含三行积分信息：

```
📊 积分情况
· 今日积分：1,234
· 今日签到：+100 积分（本次已到账）
· 明日预计：1,334（其中明日签到约 +100）
```

### 2. 账号失效的引导（通知里直接写清楚）

以前只写"请重新扫码"，用户不知道该去哪儿。现在固定给出三步：

```
1. 打开签到面板：https://你的域名
   用自己的管理员密码登录 → 点右上角「扫码登录」重新扫一次
2. 查看自己的积分：https://你的域名/me
3. 不会操作 / 需要帮处理：访问 www.example.com 联系站长
```

同样的联系方式也加在了：
- 控制台账号列表里「需重新登录」的账号下方
- 自助页 `/me` 的「微信提醒」卡片
- 签到连续失败的通知末尾

### 3. 顺带把签到通知也补齐了

每日签到成功的通知，也从「本次获得 X 积分」升级成同样的三行积分明细。

## 二、积分口径（避免误会）

| 项目 | 含义 |
|---|---|
| 今日积分 | 发通知那一刻上游返回的**实时可用积分余额** |
| 今日签到 | 本次签到**实际到账**的积分；如果今天早就签过了，会显示今日累计所得并标注「今日已签到，本次未新增」；没签上会写明原因 |
| 明日预计 | `今日积分 + 每日签到额度` 的**估算值**。额度优先取上游返回的 `daily_credit`，取不到就用今日实际所得代替。**实际以官方为准** |

> 上游没有「预测明天余额」这种接口，所以「明日预计」只能是按规则估算，文案里也写明了。

## 三、怎么开启（不用改代码）

登录通知走的是**账号级微信提醒**（Server 酱 → 个人微信），配置入口在用户的**自助页**：

1. 用户打开 `https://你的域名/me`，用管理员给的「前端账号密码」登录
2. 找到「**微信提醒**」卡片
3. 去 `sct.ftqq.com` 微信扫码 → 复制 **SendKey** → 粘进来 → 点「开启提醒」
4. 去微信关注「**Server酱**」公众号（不关注收不到）

开启后三类消息都会推给他。管理员不需要在「设置」里做任何事。

> 管理员在「设置 → 结果通知」里配的群 webhook 是**另一套**（推群里的汇总结果），两者互不影响。

### 想换「联系站长」的地址

打开 `app/service.py`，最上面的常量：

```python
SITE_OWNER = "www.example.com"
```

改这一处，所有通知、控制台失效提示、自助页文案里的联系方式会一起变。

## 六、常见问题

**Q：为什么登录后没收到通知？**
A：① 该账号没在 `/me` 里配 SendKey；② 没关注「Server酱」公众号；③ Server 酱免费版当天推送条数用完了。
   在 `/me` 点「发一条测试消息」可以单独验证通道。

**Q：一天会收到几条？**
A：正常情况 2 条：登录 1 条 + 每日签到 1 条。失效/失败各最多 1 条（每天）。

**Q：登录通知会不会重复轰炸？**
A：同账号 90 秒内只发一条；扫码失败重试、批量导入同一个号都不会连发。

**Q：「明日预计」和第二天实际到账不一致？**
A：正常。官方每日签到额度可能变动或叠加活动奖励，我们只按当前额度估算，消息里也注明了"以官方为准"。
