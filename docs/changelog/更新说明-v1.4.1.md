## 修的是什么

**点「🖥 打开电脑端登录页」后，新标签页一片空白，地址栏显示 `about:blank`。**

### 为什么会这样

原来的代码是「先向后端要一条登录链接，拿到之后再 `window.open(链接)`」：

```js
await mintLink();                              // 要连官方服务器，1~3 秒
window.open(authUrl, '_blank', 'noopener');    // 太晚了
```

浏览器有个「用户激活」机制：只有在用户点击后的**很短一段时间**（Chrome 约 5 秒）内，
`window.open()` 才被认作是你主动要开的；超过这个时间，浏览器仍然会把窗口开出来，
但**把里面的导航丢掉** —— 于是你拿到一个空白标签页，而链接本身是好的。

登录链接的申请要经过 `copilot.tencent.com`，网络慢的时候很容易超过 5 秒。

### 怎么改的

**在点击的同一个同步动作里先把窗口开出来，等拿到链接再把地址写进去**：

```js
const win = window.open('about:blank', '_blank');   // 同步，必定成功
// …这里才去 await 要链接…
win.location.replace(authUrl);                       // 给已有窗口换地址，不受激活限制
```

配套加了两层保险：

1. **占位提示** —— 空白页里立刻写上「⏳ 正在申请登录链接，请稍候…通常 1~3 秒」，
   不再是纯白页，用户知道在等什么。
2. **1.2 秒自检** —— 换完地址后回读窗口状态：如果它还停在 `about:blank`（说明导航被拦了），
   就把链接**自动复制到剪贴板**，并在按钮下方用红框提示「粘到它的地址栏回车就行」。
   （能读到 `href` 说明还是空白页；已经跳到官方站点会因为跨域读不到 —— 正好当作成功的判据。）

3. 如果连窗口都开不出来（弹窗被浏览器拦），也退化成「复制链接 + 明确提示」，不让流程断掉。

### 顺手修的

- 方式一的提示原来写到方式二卡片的提示位上（`#uploadStatus`），用户在方式一点按钮根本看不见。
  现在方式一卡片里新增了独立的提示位 `#loginHint`，提示就出现在按钮正下方。

## 升级方法

1. 上传覆盖（**不要覆盖 `data/` 目录**）
2. 重启：`systemctl restart workbuddy-checkin`（宝塔用户在「Python 项目」里点重启）
3. 刷新页面确认版本号显示 **1.4.1**
4. **浏览器强制刷新一次**（`Ctrl + F5`）—— 前端是静态文件，不清缓存可能还用着旧的 JS

> 三个页面都已设置 `Cache-Control: no-cache, must-revalidate`，正常刷新就会拿到新版 JS。
> 如果界面上还是旧样子，再按一次 `Ctrl + F5` 强制刷新（这次改的全是前端脚本，缓存没清会以为没修好）。

## 怎么验证修好了

点「🖥 打开电脑端登录页」：

- 新标签页应该先出现「⏳ 正在申请登录链接，请稍候…」
- 1~3 秒后自动变成官方登录页（有二维码）
- 如果还是空白，按钮下方会出现红框提示，并且链接已经在剪贴板里 —— 粘到地址栏就能用
