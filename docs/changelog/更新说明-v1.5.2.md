# 更新说明 v1.5.2

> 两件事：
> ① 你点「微信提醒自检」报 **Not Found** —— 不是代码坏了，是**后端还没装上去**（详见下面「为什么会 404」）。
> ② 顺着这条线又抓到一个真 bug：**「发送测试通知」不管成不成功都提示"已发送"**。这一版修掉。

---

## 为什么会 404

线上 `https://wb.example.com/api/notify/selftest` 实测返回 `{"detail":"Not Found"}`，
而老接口 `/api/notify/test` 返回 `401 未登录`（说明它存在）。

也就是说：**页面上的按钮是新的（`index.html` 传上去了），但后端还是老的**。
`/api/health` 也还是 `1.4.1`，印证了这一点。

自检/补发这两个功能分别住在 `app/service.py` 和 `app/main.py` 里，
**光换 HTML 不够，`.py` 必须覆盖 + 重启服务**。

---

## 这一版修的 bug：测试通知永远"成功"

老代码里发站长通知是这么写的：

```python
def _notify(title, content):
    ...
    requests.post(url, data=..., timeout=...)   # ← 返回值没人管
    ...
    except requests.RequestException as exc:
        logger.warning(...)                      # ← 只写服务器日志
```

`requests.post` 的返回值被直接丢掉，所以：

- Server酱 返回 `[AUTH]错误的Key` → 不检查 → 当成成功
- 企业微信 / 钉钉 返回 `errcode: 93000` → 不检查 → 当成成功
- 服务器出网被挡 → 只写一行 warning → 当成成功

`send_test_notification()` 更是无脑返回 `"测试通知已发送，请到对应的群里确认"`。

**这就是你「点了发送测试通知，也没收到消息」的原因：它在骗你。**

### 现在怎么改的

`_notify_ex()` 会把结果拆成 `(是否成功, 原因)`：

1. 先读响应体里的业务码 —— Server酱/飞书看 `code`，企业微信/钉钉看 `errcode`，飞书新版看 `StatusCode`
2. 业务码非 0 → 直接拿原始文案：`接口返回：[AUTH]错误的Key`
3. 再看 HTTP 状态码 → `接口返回 HTTP 500：...`
4. 网络异常 → `网络错误：...`

「发送测试通知」现在会把真实结果吐回前端：

- 成功 → 绿色 `测试通知已发送`
- 失败 → **红色** `发送失败：接口返回：[AUTH]错误的Key`

同时失败也会写进控制台「日志」（`站长通知没发出去：…`），不再是只进服务器文件。

## 升级方法（这次必须重启）

1. 上传覆盖这 5 个文件（保持目录结构，**别套成 `app/app/`**）：

```
app/service.py
app/main.py
app/config.py
app/__init__.py
app/static/index.html
```

2. **重启服务**：宝塔「网站 → Python 项目 → 这个项目 → 重启」
   或终端一行：`pkill -f run.py; sleep 1; cd /www/wwwroot/workbuddy-checkin && nohup python3 run.py >>data/run.log 2>&1 &`

3. **验证装没装上**（这一步别省）：浏览器打开

```
https://wb.example.com/api/health
```

- 显示 `"version":"1.5.2"` → ✅ 装好了，再去点自检
- 还是 `"version":"1.4.1"` → ❌ 文件没覆盖到正确目录，或者没重启成功

---

## 装好之后按这个顺序看

1. 控制台「设置」→ 先点 **「发送测试通知」**
   - 绿了：站长渠道正常
   - 红了：提示里写的就是原因，照着改（Key 错就重贴，HTTP 4xx/5xx 就隔会儿再试）
2. 再点 **「🔍 用户微信提醒自检」**
   - ✅ 正常 = 这条真发出去了
   - ❌ 发不出去 = 后面跟的就是 Server酱 的原话，通常是该用户的 SendKey 失效
   - ⏸ 没开提醒 = 他压根没填 SendKey，永远收不到，让他去 `/me` 开
3. 对没收到的用户，点账号行的 **「补发通知」** 立刻补一条
