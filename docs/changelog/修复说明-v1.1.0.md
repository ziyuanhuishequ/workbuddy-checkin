# v1.1.0 修复说明：登录失效 / 需要反复扫码

> 一句话：**登录态不再靠"运气"，服务器会自己续期、自己复活、域名不通自动换。**
> 正常情况下一次扫码或一次导入 refreshToken，之后就不用人管了。

---

## 一、到底坏在哪

排查时对着官方 CLI（`@tencent-ai/codebuddy-code` 2.177.x）的实际请求逐条比对，问题有四层，叠在一起就表现成"登录不了、一直要重新扫码"。

### 1. 二维码里的域名和接口域名不是同一个（这是"扫不动"的直接原因）

老代码把接口域名写死成 `copilot.tencent.com`，二维码内容就是
`https://copilot.tencent.com/login?platform=CLI&state=xxx`。

但现在这个地址已经 **302 跳到 `www.codebuddy.cn/login`** 了：

```
copilot.tencent.com/login  →  301  →  /login/  →  302  →  www.codebuddy.cn/login
```

上游把登录会话（以及 `state` 的归属）绑定在**域名**上。手机上在 `codebuddy.cn` 完成登录，我们在 `copilot.tencent.com` 轮询，两边对不上，于是永远停在「等待扫码」。

官方 CLI 早就处理了这件事（函数 `alignAuthUrlToApiOrigin`）：**二维码里的域名必须和轮询域名一致**，并且它的主站已经换成 `www.workbuddy.cn`。

### 2. 令牌续期少了三个头

官方 CLI 续期时的真实请求头：

```
POST /v2/plugin/auth/token/refresh
X-Refresh-Token: <refreshToken>
X-Auth-Refresh-Source: plugin      ← 老代码写的是 workbuddy
X-Domain: <账号 domain>             ← 老代码没带
X-Enterprise-Id: <企业 ID>          ← 老代码只在有值时才带
```

### 3. 到期时间未知的账号，永远不会续期

老逻辑：`if expires_at <= 0: return False`（= 不用续期）。
可老库迁移过来的账号、某些导入方式的账号 `expires_at` 就是 0——于是它**一辈子都不会主动续期**，等到某天接口回 401，直接被标成「需重新登录」。

### 4. 收到 401 就直接判死刑，根本不试 refreshToken

这是最要命的一条。老代码里 401 → 立刻 `status="expired"`，哪怕手里的 refreshToken 还有效。
于是「过期一下」= 「必须手动扫码」，日志里全是「凭据已失效」。

## 三、怎么升级（宝塔面板）

> 数据都在 `data/` 目录里，**升级不用重新扫码**，只要别删 `data/`。

1. 宝塔「文件」→ 进到项目目录（例如 `/www/wwwroot/workbuddy-checkin`）
2. **先把整个 `data/` 目录复制一份备份**（右键 → 复制 → 粘到别处，比如 `/www/backup/`）
3. 上传新的 `workbuddy-checkin-1.1.0.zip` 到 `/www/wwwroot/`
4. 解压覆盖（宝塔：右键压缩包 → 解压 → 目标目录选 `/www/wwwroot/` → 勾选「覆盖」）
   ```bash
   cd /www/wwwroot && unzip -o workbuddy-checkin-1.1.0.zip
   ```
   > 如果旧目录名不是 `workbuddy-checkin`，把解压出来的 `app/` 目录整个覆盖到旧目录里即可。
5. 重启服务

   **宝塔面板路径**：「网站」→「Python 项目」（或「软件商店 → 已安装 → 你的项目」）→ 找到 workbuddy-checkin → 点「重启」

   **命令行**（宝塔「终端」里粘这一行）：
   ```bash
   systemctl restart workbuddy-checkin
   ```
6. 浏览器打开控制台，右上角版本号会变成 **1.1.0**

## 四、升级后怎么确认好了

1. 设置页 →「网络」→ 点 **测试上游连通性**
   期望看到：`✅ 当前使用 https://www.workbuddy.cn，可用域名 3 个`
2. 账号列表里「需重新登录」的账号 → 点 **自动修复**
   - 能续上：提示「✅ 已自动续期并补签」
   - 续不上：说明 refreshToken 本身也过期了，只能重新扫码（这种情况点「+ 添加账号」重扫即可，**不用删旧账号**，按 uid 自动覆盖）
3. 之后什么都不用做：后台每 2 小时自动保活，签到时先续期再签。

## 五、想彻底不用扫码？用 refreshToken 导入

如果你手上有 refreshToken（比如从官方 CLI 的登录态里导出的），可以直接：

控制台 →「+ 添加账号」→「手动导入令牌」→ 把 refreshToken 粘进第一个框 → 导入。

导入成功后服务器会自己拿它换 accessToken，并一直自动续期，**只要服务器不停机太久，就不用再碰二维码**。

批量导入时也可以，每行写 `rt:你的refreshToken`。

## 六、还不行怎么办

| 现象 | 说明 |
|---|---|
| 测试连通性三个域名全红 | 服务器出不了网 / DNS 被拦，检查宝塔「安全」和机房出网策略，或在设置里配代理 |
| 自动修复提示「续期被拒绝：12153」 | refreshToken 真过期了，重新扫码 |
| 扫码一直「等待扫码」 | 先点「测试上游连通性」；再点二维码下方「在浏览器中打开登录页」用手机浏览器完成登录 |
| 签到成功但没积分 | 用账号「自检」看上游原始返回；`claim-gift` 接口上游已下线（404），属正常 |
