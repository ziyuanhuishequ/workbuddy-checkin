# v1.4.0 更新说明：删掉没用的二维码，改成「电脑端登录 + 上传令牌文件」

> 一句话：**二维码删了**（它只会误导人 —— 手机微信扫它必失败）；
> 加账号改成两条路：**① 在电脑上点一个按钮直接登录　② 把凭据文件拖进来，服务器自己解析**。
> 另外出了一份给小白看的图文教程：`用户教程-上传令牌.md`。

---

## 一、为什么删掉二维码

之前控制台和自助页都画了一个二维码，理论上"手机微信扫这个码就能登录"。**实际上这条路 100% 失败**，官方登录页自己把自己堵死了：

`www.codebuddy.cn/login/` 的 HTML 里有一段官方内联脚本（注释原文）：

> `微信内网员工探测（新版·前置）：在 React bundle 加载前就在 HTML 内联执行`
> `var isWeixin = ua.indexOf('micromessenger') !== -1 && ua.indexOf('wxwork') === -1;`
> `if (!isWeixin) { return; }` ← 电脑浏览器到这就结束，正常出页面
> `// ⚠️【微信内网员工探测 · 总开关】⚠️ 已全量放开，所有环境生效。`
> `location.replace('https://open.weixin.qq.com/connect/oauth2/authorize?...')`

结论：**只要用微信内置浏览器打开，页面第一件事就是踢你去做腾讯员工身份探测**，普通人过不去 → 最后落到「登录失败 / 请返回客户端点击「重新发起登录」重试」那个页面（页面上的二维码是"关注公众号"，不是登录入口）。

所以二维码留着只有害处：**让人以为扫一下就行，然后一直失败**。v1.4.0 把它删了。

### 实测佐证

同一条登录链接，用电脑 UA 和微信 UA 各请求一次，服务器返回的 HTML **完全一致**（23118 字节）——
说明服务端没有做任何 UA 区分，差异 100% 在浏览器里跑的那段脚本。

## 二、现在怎么加账号（两条路）

### 路 1：电脑端登录（控制台 / 自助页都有）

- 控制台「+ 添加账号」→ 第一个标签页现在是「🖥 电脑端登录」
- 一个按钮：**「🖥 打开电脑端登录页」** → 每次点击都申请一条**全新**链接并在新标签页打开
- 电脑浏览器里出现官方登录页的二维码 → 手机微信扫**电脑屏幕**上的码 → 手机点确认 → 控制台自动变 ✅
- 自助页 `/join?t=…` 同样有这个按钮；**管理员不用再给每个人单独发登录地址**，把同一个 `/join` 链接发给所有人就行

> 每次点按钮都是一条新链接（`state` 只能用一次，旧链接用过就作废）。

### 路 2：上传令牌文件（**只对装过命令行版的人有效**，别默认推荐）

> ⚠️ 这个文件**绝大多数人电脑上没有**：只有「命令行版（CLI）」登录过才生成，
> 只装桌面版 App / 只用网页版的人电脑里根本没有，**不是他操作错了**。
> 所以 `/join` 的方式二卡片顶部已经用黄框写明「大概率你没有」，并放了「🖥 好，我用方式一」的回退按钮。

- 控制台 →「+ 添加账号」→「📄 上传令牌文件」
- 自助页 →「方式二：上传令牌文件」
- 把官方客户端的 `credentials.json` **直接拖进去**（或点选文件）
- **服务器自己解析**：自动找 `accessToken` / `refreshToken` / `uid` / `domain` / 昵称，**用户不用挑字段、不用改格式**

支持的输入（全自动识别，不用手动选模式）：

| 你给的内容 | 能不能认 |
|---|---|
| 整份凭据文件（JSON，单个对象 / 数组 / 多层嵌套，如 `credential.user.uid`） | ✅ |
| 前后夹了说明文字的 JSON（用户连正文一起复制了） | ✅ |
| 一行一个令牌（`token` / `token,uid,domain,昵称`） | ✅ |
| `rt:` 开头的 refreshToken | ✅ |
| 重复内容 | ✅ 自动去重 |
| 传错文件（安装包 / 日志 / 随便一段话） | ❌ 明确报错：「没能从内容里找到 accessToken / refreshToken」 |

## 三、代码改动

| 位置 | 改动 |
|---|---|
| `app/qrlogin.py` | 删掉 `qrcode` 依赖与 `qr_data_url()`，只发登录链接；文案改成"链接过期"而不是"二维码过期" |
| `app/service.py` | 新增 `parse_credentials_text()` / `_walk_credentials()` / `_pick_deep()` / `_loads_forgiving()`：任意 JSON 结构里挖令牌，字段名大小写/下划线不敏感，uid 支持 `credential.user.uid` 这种嵌套 |
| `app/service.py` | `import_batch()` 改为先自动解析再逐条导入，额外返回 `account_ids` |
| `app/main.py` | 新增 `POST /api/join/import?t=…`：自助页上传用，走同一套令牌鉴权 + 限流，**只返回刚导入那个账号的凭据**，256KB 上限，关闭"允许手动导入"时直接 403 |
| `app/main.py` | `/api/qr/start`、`/api/join/qr` 不再返回 `qr` 字段 |
| `requirements.txt` | **去掉 `qrcode[pil]`** —— 少装一个依赖，`pip install` 更快更不容易失败 |
| `app/static/index.html` | 添加账号弹窗重做：两个标签页 + 文件拖拽/选择 + 解析结果弹窗（成功数量、失败原因、账号密码一键复制）；全站「扫码」文案改成「电脑端登录」 |
| `app/static/join.html` | 整页重写：删二维码，改成「方式一 电脑端登录（按钮直接打开）」+「方式二 上传令牌文件」；手机/微信打开时自动提示"复制本页链接发到电脑"，并**隐藏**那个点了也没用的按钮 |
| `app/static/join.html` / `index.html` | **修一个会让人看到空白页的坑**：点「打开电脑端登录页」后新标签页停在 `about:blank`。原因是申请链接要连官方服务器（1~3 秒），`await` 回来再 `window.open()` 时浏览器已经不认这是用户操作，于是只开了个空窗口、导航被丢掉。改成**点击瞬间同步开窗口**、拿到链接后 `win.location.replace(url)`；并加 1.2 秒自检：若仍停在 `about:blank` 就自动复制链接 + 在按钮下方提示，保证不会对着空白页干等 |
| `app/static/join.html` | 方式一卡片内新增 `#loginHint` 提示位（原来提示写进了方式二的 `#uploadStatus`，用户看不见） |
| 新增 | `用户教程-上传令牌.md`：给完全不懂电脑的人写的 0～4 步 + 7 条常见问题 |

## 四、升级方法

> 版本号必须变成 **1.4.0** 才算生效。

1. 备份 `data/` 整个目录
2. 上传 `workbuddy-checkin-1.4.0.zip` → 解压覆盖（**不要覆盖 `data/`**）
3. 重启：网站 →「Python项目」→ 项目行右侧「重启」；没有这个菜单就用「终端」执行 `systemctl restart workbuddy-checkin`
4. 浏览器 `Ctrl+F5` 强刷 → 右上角显示 **1.4.0**

**依赖变了**：去掉了 `qrcode`。老环境不卸也能跑（只是多装了一个没用的包），想干净可以：

```bash
cd /www/wwwroot/workbuddy-checkin
./venv/bin/pip uninstall -y qrcode pillow
```

> 只替换 `app/static/*.html` 两个文件也能立刻看到新界面（不用重启，静态文件是按请求读的），
> 但「上传令牌文件」要用到新接口 `/api/join/import`，那个必须重启。

## 五、兼容性

- 数据库**不用迁移**，账号、签到记录、清理设置全部不动
- 老账号不受影响，照常自动续期、自动签到
- `/join` 链接（`?t=…`）格式没变，之前发出去的链接照样能用
- 去掉二维码后，服务器不再需要 `qrcode` / `Pillow` 两个包，安装失败率明显下降（这两个包在没网/缺编译环境的机器上最容易装不上）
