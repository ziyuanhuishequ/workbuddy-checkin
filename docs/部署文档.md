## 0. 前置检查

| 项 | 要求 |
|---|---|
| 系统 | CentOS 7+ / Ubuntu 20.04+ / Debian 11+，x86_64 或 arm64 都行 |
| 宝塔 | 面板 7.x 以上，已装好 Nginx |
| Python | **3.8 或更高**（脚本会自动找；找不到会用宝塔的 Python 项目管理器里的版本） |
| 出网 | 服务器能访问 `copilot.tencent.com`（这是签到接口的域名） |
| 内存 | 300MB 以上空闲足够（本工具很轻） |

在宝塔「终端」里确认一下 Python 版本：

```bash
python3 --version
```

如果低于 3.8 或提示找不到命令：

```bash
# CentOS / 宝塔
yum install -y python3 python3-pip
# Ubuntu / Debian
apt update && apt install -y python3 python3-venv python3-pip
```

## 方式一：一键脚本（推荐）

### 1. 上传并解压

1. 宝塔左侧菜单「**文件**」→ 进入 `/www/wwwroot/`
2. 点上方「**上传**」，把 `workbuddy-checkin-1.0.0.zip` 传上去（约 75 KB，秒传）
3. 传完后在文件列表里**右键这个压缩包 → 解压**
4. 解压得到 `/www/wwwroot/workbuddy-checkin/`，进去应该能看到 `run.py`、`app/`、`deploy/`、`requirements.txt`

> **如果解压后套了一层目录**（路径变成 `/www/wwwroot/workbuddy-checkin/workbuddy-checkin/`），
> 把里层内容全部剪切到外层，或者安装时显式指定路径：
> `APP_DIR=/www/wwwroot/workbuddy-checkin/workbuddy-checkin bash deploy/install-bt.sh`

> 也可以用 `.tar.gz` 包，在宝塔终端里：
> `mkdir -p /www/wwwroot && tar xzf workbuddy-checkin-1.0.0.tar.gz -C /www/wwwroot`

### 2. 执行安装脚本

宝塔左侧「**终端**」（或者网站 → 该目录 → 终端）里执行：

```bash
cd /www/wwwroot/workbuddy-checkin
bash deploy/install-bt.sh
```

脚本会依次完成：

1. 找到可用的 Python 3.8+ 解释器（会自动找宝塔 Python 项目管理器里装的版本）
2. 复制代码到安装目录、创建独立虚拟环境、安装依赖
   - **国内服务器专用**：官方 PyPI 拉不动时会**自动切换清华镜像**重试
3. 生成 `.env`（里面是随机强密码）
4. 写入并启动 `workbuddy-checkin` systemd 服务
5. **跑一次接口自检**（会真实调用一次上游申请登录链接，验证链路通不通）
6. 打印访问地址、控制台密码、常用命令，以及下一步加反向代理的操作

脚本**可以重复执行**，已经做过的步骤会跳过或覆盖，不会弄坏已有数据。

**如果中途报错**：脚本会打印「在第几行中断」和退出码。把从 `bash deploy/install-bt.sh`
开始到最后的**完整输出**复制下来，就能定位问题。常见的有：

| 报错 | 原因 |
|---|---|
| `找不到 Python 3.8 及以上版本` | 服务器只有 Python 3.6。装宝塔「Python项目管理器」再装个 3.10+ 后重跑 |
| `创建虚拟环境失败` | 缺 `python3-venv`：`apt install -y python3-venv` |
| `依赖安装失败` | 出网被限。可先在服务器上配好代理，或手动指定镜像源安装 |
| `服务启动失败` + 端口占用 | 换端口重跑：`PORT=9448 bash deploy/install-bt.sh` |

最后你会看到类似输出：

```
════════════════════════════════════════════════════════════
 ✅ 部署完成
════════════════════════════════════════════════════════════
 服务名    ：workbuddy-checkin
 本机地址  ：http://127.0.0.1:8848
 控制台密码：xxxxxxxxxxxx
 数据目录  ：/www/wwwroot/workbuddy-checkin/data
════════════════════════════════════════════════════════════
```

**把密码记下来**（也保存在 `/www/wwwroot/workbuddy-checkin/.env` 里）。

### 3. 换端口 / 换目录（可选）

```bash
PORT=9448 APP_DIR=/opt/workbuddy-checkin bash deploy/install-bt.sh
```

### 4. 继续往下看

服务只监听 `127.0.0.1:8848`，**还需要配反向代理才能用浏览器访问** → 跳到 [配置 Nginx 反向代理 + HTTPS](#配置-nginx-反向代理--https)。

## 方式二：宝塔 Python 项目管理器（纯图形化）

不想敲命令就走这条。

### 1. 上传代码

宝塔「文件」→ 进入 `/www/wwwroot` → 上传 `workbuddy-checkin` 目录（或上传 zip 后右键解压）。

最终路径假设是 `/www/wwwroot/workbuddy-checkin`，进去应该能看到 `run.py`、`app/`、`requirements.txt`。

### 2. 安装 Python 项目管理器

「软件商店」→ 搜索 **Python项目管理器** → 安装。

> 较新版本的宝塔把它叫做 **「Python项目」**，入口在「网站」→「Python项目」，操作类似。

### 3. 添加项目

打开插件 → **添加项目**，按下表填写：

| 字段 | 填写 |
|---|---|
| 项目名称 | `workbuddy-checkin` |
| 项目路径 | `/www/wwwroot/workbuddy-checkin` |
| Python 版本 | 选 3.8 以上的（没有就先在插件里安装一个） |
| 框架 | 选「其他」 |
| 启动方式 | `python` |
| 启动文件 | `run.py` |
| 项目端口 | `8848` |
| 是否安装依赖 | 勾选，依赖文件填 `requirements.txt` |

提交后等待依赖安装完成。

### 4. 环境变量（可选）

如果面板有「环境变量」设置项，加上：

```
WB_HOST=127.0.0.1
WB_PORT=8848
WB_PASSWORD=你想要的强密码
WB_DATA_DIR=/www/wwwroot/workbuddy-checkin/data
WB_TZ_OFFSET=8
```

> **如果面板版本不支持环境变量**，直接启动也能用：程序会自动生成密码并写入
> `/www/wwwroot/workbuddy-checkin/data/password.txt`，打开这个文件就能看到密码。

### 5. 启动

点「启动」，然后看日志确认出现 `Uvicorn running on http://127.0.0.1:8848`。

## 方式三：Docker

宝塔「软件商店」→ 安装 **Docker管理器**，然后在终端里：

```bash
cd /www/wwwroot/workbuddy-checkin
echo "WB_PASSWORD=换成你的强密码" > .env
docker compose up -d --build
docker compose logs -f          # 看启动日志（Ctrl+C 退出查看，不影响容器）
```

容器默认把端口绑在 `127.0.0.1:8848`，对外仍然要走 Nginx 反代。

数据持久化在宿主机的 `./data` 目录，备份它即可。

常用命令：

```bash
docker compose ps
docker compose restart
docker compose down
docker compose up -d --build   # 改了代码后重建（不加 --build 不会生效！）
```

## 配置 Nginx 反向代理 + HTTPS

### 图形化（推荐）

1. 宝塔「网站」→ **添加站点**，填你的域名（比如 `wb.example.com`），不要创建数据库和 PHP。
2. 点刚建好的站点 →「设置」→ 左侧 **反向代理** → **添加反向代理**：

   | 字段 | 填写 |
   |---|---|
   | 代理名称 | `workbuddy` |
   | 目标 URL | `http://127.0.0.1:8848` |
   | 发送域名 | `$host` |

   提交。

3. 同一个「设置」窗口 → 左侧 **SSL** → 选 **Let's Encrypt** → 勾选域名 → 申请。申请成功后打开 **「强制 HTTPS」**。

4. 浏览器打开 `https://wb.example.com`，输入控制台密码登录。

### 手动配置

参照 [`deploy/nginx.conf.example`](deploy/nginx.conf.example)，改掉里面的域名和证书路径，放到
`/www/server/panel/vhost/nginx/` 下，然后 `nginx -t && nginx -s reload`。

手动配置里已经带了几个安全响应头（`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`）。

> **用户自助页** `https://你的域名/me` 和管理员控制台在同一个站点下，**不需要额外配置**。
> 把 `https://你的域名/me` 连同「前端账号密码」一起发给对方即可。

## 防火墙

**不要把 8848 端口对外开放。** 服务只监听回环地址，走 Nginx 的 80/443 就够了。

检查一下：

- 宝塔「安全」页 → 确认没有放行 `8848`
- 云服务器厂商控制台的安全组 → 同样不要放行 `8848`
- 只放行 `80`、`443`（以及 SSH 端口）

## 日常运维

```bash
# 状态
systemctl status workbuddy-checkin

# 实时日志
journalctl -u workbuddy-checkin -f

# 重启（改了 .env 之后必须重启）
systemctl restart workbuddy-checkin

# 停止 / 启动 / 开机自启
systemctl stop workbuddy-checkin
systemctl start workbuddy-checkin
systemctl enable workbuddy-checkin
```

应用日志同时写到 `data/app.log`（自动轮转，保留 3 份）。

### 升级

```bash
# 1. 备份数据（最重要）
cp -r /www/wwwroot/workbuddy-checkin/data /root/wb-data-backup-$(date +%F)

# 2. 覆盖代码（保留 data 目录和 .env）
#    用宝塔「文件」上传新代码，或解压覆盖

# 3. 更新依赖并重启
cd /www/wwwroot/workbuddy-checkin
./venv/bin/python -m pip install -r requirements.txt
systemctl restart workbuddy-checkin
```

### 备份

只需要备份 **`data/` 目录**（含数据库、加密密钥、日志）和 **`.env`**。

```bash
tar czf /root/workbuddy-$(date +%F).tar.gz \
    -C /www/wwwroot/workbuddy-checkin data .env
```

> ⚠️ `data/` 里有全部账号的加密凭据，**不要放到公开网盘或仓库**。`secret.key` 和 `data/` 必须一起备份，
> 否则恢复后令牌解不开（重新添加一次即可，但每个账号都得重来）。

恢复：把 `data/` 和 `.env` 放回原位，`systemctl restart workbuddy-checkin`。

### 卸载

```bash
systemctl disable --now workbuddy-checkin
rm -f /etc/systemd/system/workbuddy-checkin.service
systemctl daemon-reload
rm -rf /www/wwwroot/workbuddy-checkin
```

## 排障速查

| 现象 | 原因 / 处理 |
|---|---|
| `找不到 Python 3.8+` | 按 [前置检查](#0-前置检查) 安装 python3 / python3-venv |
| `创建虚拟环境失败` | Debian/Ubuntu 缺包：`apt install -y python3-venv` |
| 服务起不来 | `journalctl -u workbuddy-checkin -n 50` 看具体报错 |
| 浏览器打不开站点 | 确认反向代理目标填的是 `http://127.0.0.1:8848`；`curl -I http://127.0.0.1:8848/api/health` 在服务器上先自测 |
| 页面能开但接口 502 | Nginx 到了、后端挂了，查 `systemctl status` |
| 「申请登录链接失败」 | 服务器连不上 `copilot.tencent.com`。测：`curl -I https://copilot.tencent.com`；需要代理就在设置页填写 |
| 一直「等待登录」 | 手机确认后等几秒；仍无反应就回弹窗点一次「打开电脑端登录页」重新申请（链接是一次性的） |
| 账号显示「需重新登录」 | 凭据失效，重新添加一次（按 uid 自动覆盖，不用先删）；走「上传令牌文件」最快 |
| 忘记控制台密码 | `cat /www/wwwroot/workbuddy-checkin/.env` 或 `data/password.txt` |
| 用户打不开 `/me` | 确认反向代理没有拦住 `/me` 路径（默认整站代理就不会有问题） |
| 用户说登录不了自助页 | 让他确认用的是**前端账号**（形如 `wb001`）而不是 WorkBuddy 昵称 |
| 用户忘了自助页密码 | 管理端账号列表点「前端」，账号密码和登录地址直接显示出来，复制给他即可 |
| 想让对方的旧密码失效 | 点「前端」→「重置密码」，生成一个新的，旧密码立即失效 |
| 添加时没记下前端密码 | 不要紧，事后在账号列表点「前端」随时能查看和复制 |
| 想换密码 | 改 `.env` 里的 `WB_PASSWORD` → `systemctl restart workbuddy-checkin` |
| 签到时间不对 | 设置页的时区是服务器时区。容器里是 UTC+8；用 `date` 确认服务器时间 |

部署完之后，建议跑一次自检确认全链路正常：

```bash
cd /www/wwwroot/workbuddy-checkin
./venv/bin/python tools/selftest_api.py http://127.0.0.1:8848 你的控制台密码
```
