## 一、三个页面，三种角色

整套东西只有三个页面，对应三种人：

| 页面 | 地址 | 谁用 | 要什么凭据 |
|---|---|---|---|
| **管理控制台** | `https://你的域名` | **只有你** | 控制台密码 |
| **自助登录页** | `https://你的域名/join?t=令牌` | 别人（你发给谁谁能用） | 不需要 |
| **用户自助页** | `https://你的域名/me` | 别人 | 每人一套 `wb00X` + 密码 |

**它们之间的关系：**

```
你：控制台 ──→ 能看到所有账号、所有数据
用户：/join ──登录 / 上传令牌──→ 拿到自己的一套凭据 ──→ 登录 /me 看自己的数据
                                    ↑
                          只能看到自己那一个账号
```

**关键设计：用户永远碰不到你的控制台，也看不到任何别人的账号。**
每个用户在自己那套凭据下，只能查到自己那一个账号的积分、签到记录。

## 二、地址与密码

### 你要记住的两个

**① 控制台地址 + 密码**（只有你用）

```
地址：https://你的域名
密码：安装时脚本打印的那串（16 位左右）
```

忘了密码？服务器终端里查：

```bash
grep WB_PASSWORD /www/wwwroot/workbuddy-checkin/.env
```

想改密码？编辑 `.env` 里那行 `WB_PASSWORD=`，然后：

```bash
systemctl restart workbuddy-checkin
```

改密码**不影响任何账号数据**，只是你得用新密码登录。

**② 自助登录链接**（发给别人）

在控制台「**设置**」页 →「**分享给他人自助登录**」→ 点「**复制链接**」。

形如：

```
https://你的域名/join?t=xxxxxxxxxxxxxxxxxxxx
```

> ⚠️ 这条链接**谁拿到谁就能加账号**。只发给你信任的人。如果外流了，点「**换一个新链接**」，旧链接立刻失效（已添加的账号不受影响）。

### 用户的账号密码在哪看

控制台 → 账号列表 → 点那一行的「**前端**」按钮，会显示：

```
前端账号   wb001
前端密码   xxxxxxxxxx
登录地址   https://你的域名/me
```

点「复制账号密码和地址」直接转交。**密码是加密保存的，随时可以再查**；忘了就点「重置密码」生成一个新的。

## 三、日常怎么用

### 你是管理员

**加账号（两种方式，任选一种）：**

**方式一 · 电脑端登录**
1. 在**电脑**上打开控制台 → 右上角「**+ 添加账号**」→ 标签页「🖥 电脑端登录」
2. 点「**🖥 打开电脑端登录页**」→ 会新开一个标签页，里面显示官方登录页的**二维码**
3. **手机微信扫电脑屏幕上那个二维码** → 手机上点「确认登录」
4. 控制台弹窗自动变成 ✅，并显示「前端账号 / 前端密码 / 登录地址」，点「复制」发给对方

**方式二 · 上传令牌文件（只对装过命令行版的人有效，别默认推荐）**
> ⚠️ **这个文件绝大多数用户电脑上没有**：它只有「命令行版（CLI）」登录过才会生成，
> 只装桌面版 App / 只用网页版的人电脑里根本没有，**不是他操作错了**。
> **发给普通人时一律先引导「方式一」**，别让他先去找文件 —— 找不到他会以为是自己笨，白耗半小时。
> `/join` 页的方式二卡片顶部已经用黄框写明这一点，并放了一个「🖥 好，我用方式一」的回退按钮。

1. 先确认对方是「装过命令行版」的人，再让他找：`%USERPROFILE%\.codebuddy\instances\credentials*.json`
2. 控制台「+ 添加账号」→「📄 上传令牌文件」，或直接把 `/join` 链接发给用户让他自己传
3. **把整份文件拖进去**就行 —— 服务器自己解析令牌、uid、域名，不用挑字段
4. 详细图文（可直接转发给用户）：[用户教程-上传令牌.md](用户教程-上传令牌.md)

> ⚠️ **不要指望"手机微信扫一扫就登录"**：微信内置浏览器打开官方登录页时，会被官方脚本强制跳去做"内网员工身份探测"，普通人过不去，最后一定落到「登录失败」那个页面。
> 所以 v1.4.0 已经把二维码从界面上去掉了 —— 能在电脑浏览器里打开、扫电脑屏幕上的码，才是唯一可行的扫码方式。

**看状态：**

| 列 | 含义 |
|---|---|
| 登录态 | `正常` = 凭据有效；`需重新登录` = 掉了，要重新登录一次（或重新上传令牌） |
| 今日签到 | `已签到` / `今日未签` / `签到失败` |
| 积分余额 | 实时余额（斜杠后面是总额度） |
| 今日获得 | 今天签到到账多少积分 |
| 令牌到期 | 凭据过期时间（会自动续期，一般不用管） |

**常用操作：**

- **一键全部签到** —— 立刻把所有账号签一遍
- **全部自检** —— 逐个查询真实状态（积分、签到情况），确认凭据还有效
- **暂停 / 恢复** —— 暂时不签某个号，凭据保留
- **退出登录** —— 删除该账号的全部凭据（不影响对方的 WorkBuddy 账号本身）
- **🧹 清理失效账号** —— 批量清掉所有「需重新登录」的僵尸号（可选按失效天数过滤）。
  只在真有失效账号时才出现；**只删本服务器的凭据**，WorkBuddy 账号本身不受影响。
  也可以在「设置 → 签到」里设成失效满 N 天自动清理。

### 别人自助添加

把 `/join` 链接发给他（**同一个链接发给所有人就行**），他打开后：
- 在电脑上点「🖥 打开电脑端登录页」→ 微信扫电脑屏幕上的码 → 当场拿到自己的账号密码；
- 或者用「方式二：上传令牌文件」，把 `credentials.json` 拖进去 → 服务器解析后同样拿到账号密码
  （**仅当他自己电脑上确实有这个文件**；没有就走上面的方式一，别在这条路上磨）。

> 手机上/微信里打开 `/join` 时，页面会自动提示"请复制本页链接到电脑打开"，并隐藏掉那个点了也没用的按钮。

页面上会提示他：想每天收微信提醒，就登录 `/me` 配一个 Server 酱。

### 用户自己查积分

打开 `https://你的域名/me`，用 `wb001` + 密码登录，能看到：

- **可用积分**（余额 / 总额度）
- **今日签到**状态、**今日获得**多少积分
- **累计签到成功次数**
- **最近 30 天签到记录**
- 每天几点自动签到、下次还有多久、凭据是否自动续期

还能自己：

- **暂停 / 恢复**自己的自动签到
- **开启微信提醒**（每日结果 + 失效警告）
- **修改自己的密码**
- **退出登录并删除凭据**（一键把自己从服务器上完全移除）

## 四、从零部署到服务器

### 环境要求

| 项 | 要求 |
|---|---|
| 系统 | CentOS 7+ / Ubuntu 20.04+ / Debian 11+，x86_64 或 arm64 |
| 面板 | 宝塔面板，已装好 Nginx |
| Python | **3.8 或更高，且必须带 `_ssl` 模块**（见下方踩坑记录） |
| 出网 | 服务器能访问 `copilot.tencent.com` |
| 内存 | 空闲 300MB 足够 |

### 部署步骤

**① 上传源码包**

宝塔「文件」→ 进入 `/www/wwwroot/` → 点「上传」→ 选 `workbuddy-checkin-1.0.0.zip`

**② 解压**

右键压缩包 →「解压」。
> 🚨 「解压到」那一栏必须是 `/www/wwwroot`，**不要**带 zip 的名字（否则会套一层目录）。
> 解压完路径应该是 `/www/wwwroot/workbuddy-checkin/`，里面有 `run.py`、`app/`、`deploy/`。

**③ 一键安装**

宝塔「终端」里手打：

```bash
cd /www/wwwroot/workbuddy-checkin
```

```bash
bash deploy/install-bt.sh
```

脚本会自动：找 Python → 建虚拟环境 → 装依赖（官方源失败自动切清华镜像）→ 生成随机密码 → 注册 systemd 服务 → 跑一次接口自检 → 打印访问地址和密码。

**如果提示找不到 Python 3.8+**，手动指定解释器再跑：

```bash
PY=/你的/python3路径 bash deploy/install-bt.sh
```

**④ 配域名访问**

服务只监听 `127.0.0.1:8848`，要用域名访问得加反向代理：

1. 宝塔「网站」→ **添加站点** → 域名填你的域名（**不要**建数据库和 PHP）
2. 点该站点 →「设置」→「**反向代理**」→ **添加反向代理**：

   | 字段 | 填 |
   |---|---|
   | 代理名称 | `workbuddy` |
   | 目标 URL | `http://127.0.0.1:8848` |
   | 发送域名 | `$host` |

3. 同一个「设置」窗口 →「**SSL**」→ Let's Encrypt → 勾选域名 → 申请 → 成功后打开「**强制 HTTPS**」

**⑤ 开始用**

浏览器打开 `https://你的域名`，输控制台密码，然后「+ 添加账号」登录一次即可。

### ⚠️ 那次踩过的坑（CentOS 7 一定要看）

**症状**：装依赖时报

```
WARNING: pip is configured with locations that require TLS/SSL,
however the ssl module in Python is not available.
```

**原因**：宝塔「Python项目管理器」编译 Python 时**没有链上 OpenSSL**（CentOS 7 自带 OpenSSL 1.0.2，而 Python 3.8+ 需要 1.1.1+），结果 `_ssl` 模块压根没编出来。**这个 Python 发不出任何 HTTPS 请求**，就算绕过 pip 装上依赖，工具也跑不起来。

先确认（把路径换成你实际的）：

```bash
/www/server/python_manager/versions/3.8.12/bin/python3 -c "import _ssl"
```

- 报 `No module named '_ssl'` → 模块没编出来，**必须换 Python**
- 报 `libssl.so.1.1: cannot open shared object file` → 只是缺库，`yum install -y openssl11-libs` 可能就够

**解决办法：装 Miniconda（自带完整 OpenSSL，不碰系统那套）**

注意：**不能用最新的 Miniconda**，它要 glibc 2.28，而 CentOS 7 只有 2.17。用 2023 年的版本：

```bash
cd /root
```

```bash
B=https://mirrors.tuna.tsinghua.edu.cn/anaconda/miniconda/
```

```bash
curl -O ${B}Miniconda3-py39_23.5.2-0-Linux-x86_64.sh
```

```bash
mv Miniconda3-py39_23.5.2-0-Linux-x86_64.sh m.sh
```

```bash
bash m.sh -b -p /opt/miniconda3
```

验证它带 SSL（**必须打印出版本号**）：

```bash
/opt/miniconda3/bin/python3 -c "import ssl; print(ssl.OPENSSL_VERSION)"
```

然后用它装：

```bash
export PY=/opt/miniconda3/bin/python3
```

```bash
cd /www/wwwroot/workbuddy-checkin
```

```bash
bash deploy/install-bt.sh
```

> 🚨 **千万不要删 `/opt/miniconda3`** —— 服务的 Python 就是它。

**其他坑**：

| 现象 | 原因 |
|---|---|
| `Installer requires GLIBC >=2.28` | 用了最新版 Miniconda，换成 `23.5.2-0` |
| 服务重启后新接口报 404 | **页面文件换了但进程没重启**。Python 代码要 `systemctl restart` 才生效 |
| 终端命令报 `[root@xxx: command not found` | 复制时把提示符 `[root@...]#` 一起粘进去了，只复制 `#` 后面的内容 |

## 五、日常维护

### 常用命令

```bash
systemctl status  workbuddy-checkin      # 看状态（q 退出）
systemctl restart workbuddy-checkin      # 重启（改了 .env 必须重启）
systemctl stop    workbuddy-checkin      # 停止
journalctl -u workbuddy-checkin -f       # 实时日志（Ctrl+C 退出）
journalctl -u workbuddy-checkin -n 50 --no-pager   # 最近 50 行
```

应用日志另外写在 `data/app.log`（自动轮转，保留 3 份）。

### 备份

**只需要备份 `data/` 目录和 `.env`**：

```bash
cp -r /www/wwwroot/workbuddy-checkin/data /root/wb-backup-$(date +%F)
```

> ⚠️ `data/` 里有全部账号的加密凭据和 `secret.key`。**两者必须一起备份**——只恢复数据库没有密钥的话，所有令牌都解不开，得全部重新登录。

### 升级

```bash
cp -r /www/wwwroot/workbuddy-checkin/data /root/wb-backup
```

上传新的 zip → 解压覆盖到 `/www/wwwroot` → 重启：

```bash
systemctl restart workbuddy-checkin
```

> 数据库结构变化会在服务启动时**自动迁移**，老账号数据不受影响。

### 卸载

```bash
systemctl disable --now workbuddy-checkin
```

```bash
rm -f /etc/systemd/system/workbuddy-checkin.service
```

```bash
systemctl daemon-reload && rm -rf /www/wwwroot/workbuddy-checkin
```

## 六、设置项说明

控制台「设置」页，改完点保存**立即生效**，不用重启。

| 设置 | 默认 | 说明 |
|---|---|---|
| 每日签到时间 | `09:00` | 服务器时区（东八区） |
| 启动时补签 | 开 | 服务重启后，补签当天还没签的账号 |
| 自动续期令牌 | 开 | 强烈建议保持开启 |
| 提前续期时间 | 30 分钟 | 距过期不足这个时间就续期 |
| 失败重试间隔 | 30 分钟 | 当天签到失败后多久重试 |
| 每天最多重试 | 3 次 | 单账号上限 |
| 上游代理 | 空 | 如 `http://127.0.0.1:7890` |
| 自动清理失效账号 | `0`（关闭） | 失效满 N 天自动删除该账号凭据；`0` = 不自动清理 |
| 通知方式 / 时机 / 地址 | 不通知 | 管理员级别的汇总通知（详见第七节） |
| 分享给他人自助登录 | 开 | 自助入口开关，可一键换链接 |
| 一键退出全部账号 | — | **危险操作**，清空所有凭据 |

## 七、微信提醒

**有两套，互不干扰：**

| | 管理员通知 | 用户通知 |
|---|---|---|
| 在哪配 | 控制台「设置」→ 结果通知 | 用户自己在 `/me` →「微信提醒」 |
| 谁收 | 你 | 每个人自己 |

**用户通知**：用户添加账号后，页面会提示他去 `/me` 开启。开启后每天签到完收到一条微信（结果 + 积分），凭据失效时单独收到警告。同一个话题**每天最多推一条**，不会轰炸他。

**管理员通知**：

- 想推**个人微信** → 选「Server 酱」，去 <https://sct.ftqq.com/> 微信扫码拿 SendKey，填进来，**再去微信关注「Server酱」公众号**（不关注收不到）
- 用**钉钉** → 建机器人时「安全设置」**必须选「自定义关键词」并填 `WorkBuddy`**；选了「加签」会一直发不出去
- 推送时机建议选「**仅失败时**」，平时不打扰

## 八、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 浏览器打不开站点 | 反向代理配了吗？先在服务器上测：`curl -s http://127.0.0.1:8848/api/health` |
| 提示密码不对 | 分清你在哪个页面：控制台用**控制台密码**，`/me` 用**前端账号密码**。也可能是浏览器自动填充了旧密码，试试无痕窗口 |
| 点「开启提醒」报 404 | 服务没重启。`systemctl restart workbuddy-checkin` 后再刷新页面 |
| 「申请登录链接失败」 | 服务器连不上上游。测：`curl -I https://www.workbuddy.cn` |
| 点了「打开电脑端登录页」一直没反应 | 看有没有被浏览器拦弹窗；也可以点「复制登录链接」自己粘到电脑浏览器 |
| 上传令牌文件提示「没能从内容里找到 accessToken」 | 传错文件了。要的是 `credentials*.json`，不是安装包/日志 |
| 官方登录页提示「登录失败 / 请返回客户端重新发起」 | **先看是不是这两件事**：① 官方给每条链接的 `state` **只能用一次**，反复打开同一份链接就永远是这个错 —— 每次点「🖥 打开电脑端登录页」都会重新申请一条；② 在**微信内置浏览器**里打开会被官方脚本强制跳去做"内网员工探测"，普通用户过不去 → 发到**电脑浏览器**打开，再扫电脑屏幕上的二维码 |
| 电脑浏览器打开链接后直接显示「登录失败」（连二维码都没有） | 这条链接已经用过了或过期了。回弹窗点一次「🖥 打开电脑端登录页」重新拿一条，别复用旧地址 |
| 「问题标识：xxxx」是干什么的 | 官方回调页的请求 id，只有联系官方客服排查时才用得上，对你的登录没有其他作用 |
| 每次登录「今日获得」都加 100 | 1.3.1 已修。老版本的签到接口不幂等，重扫会重复领；现在按 uid+日期记账，一天只领一次 |
| 失效账号太多想清掉 | 账号页点「🧹 清理失效账号」；或「设置 → 签到」里设失效满 N 天自动清理 |
| 同一个号添加了好几次 | 账号不会重复。**同一天重复登录只记一次**，第二次会提示「今天已经添加过了」，凭据照常显示 |
| 账号显示「需重新登录」 | 先点该账号的「自动修复」（用 refreshToken 自动续期）；修不回来再重新登录添加（按 uid 自动覆盖，不用先删） |
| 积分/昵称不显示 | 点该账号的「自检」，会显示上游返回的原始错误 |
| 用户看不到别人的数据吗 | 看不到。接口只返回他刚扫的那一个账号的凭据 |
| 忘记控制台密码 | `grep WB_PASSWORD /www/wwwroot/workbuddy-checkin/.env` |

## 九、安全须知

- 凭据（accessToken / refreshToken / 前端密码 / Server 酱 SendKey）**全部加密后存在你自己的服务器上**，用 `data/secret.key` 派生密钥。不会上传到任何第三方
- 控制台**强制要求密码**，不会以空密码启动。会话 Cookie 是 HttpOnly + SameSite=Lax 的签名令牌，登录失败会限流
- **管理员和用户令牌严格隔离**：用户拿着自己的令牌也调不动任何管理接口
- 自助登录入口有**令牌 + 限流**（同一 IP 每小时限额），可一键作废重发
- 服务默认**只监听 `127.0.0.1`**，请通过 Nginx 反向代理 + HTTPS 对外提供
- **不要放行 8848 端口到公网**
- `data/` 目录含全部凭据，**备份时注意保管，不要提交到 Git**
